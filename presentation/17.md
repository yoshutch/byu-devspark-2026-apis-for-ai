# Better APIs help every consumer

Improving the API contract makes it better for:

- **humans**: clearer requests, responses, and recovery guidance;
- **AI agents**: discoverable operations and predictable structured errors;
- **generated clients**: explicit schemas, stable types, and machine-readable failures.

## Other concepts for API improvement

- API security ~ APIs are (or will be) the #1 attack vector
    - ALWAYS authenticate and authorize incoming requests (trust no one)
    - Protect against OWASP top 10
    - etc.
- API versioning ~ can the contract evolve without surprising consumers?
    - Additive changes
    - Clear sunset and deprecation warnings
- Asynchronous support ~ 202 Accepted response
- Semantic layer ~ clearly define what words mean, not just their contract
- DON'T return dynamic response formats ~ keep the structure dependable
    - Return `null` on fields instead of removing them
    - Standard envelope response body
    - Use a different endpoint for different response bodies
