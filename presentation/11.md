# Handle conflicts explicitly

The API must enforce the business rule:

**Business rule:** An advisor cannot have two appointments in the same time slot.

One request succeeds. The other receives a clear conflict:

```http
409 Conflict
Content-Type: application/problem+json

{
  "type": "https://example.edu/problems/appointment-slot-unavailable",
  "title": "Appointment slot unavailable",
  "status": 409,
  "code": "APPOINTMENT_SLOT_UNAVAILABLE",
  "detail": "The requested appointment slot is no longer available."
}
```

An explicit conflict gives the client a safe next step:

- Ask the user to choose another time.
- Offer available alternatives.
- Do not silently create a different appointment.

> [!Important]
> A machine can respond to an explicit conflict, but it cannot safely recover from an ambiguous success.
