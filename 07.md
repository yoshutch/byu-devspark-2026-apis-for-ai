# Make authorization and auditing explicit

The API should distinguish identity from permission:

```text
Authentication: Who is making this request?
Authorization: What is that caller allowed to do?
```

```http
401 Unauthorized
```

The caller is missing valid authentication.

```http
403 Forbidden
Content-Type: application/problem+json

{
  "type": "https://example.edu/problems/appointment-not-permitted",
  "title": "Appointment not permitted",
  "status": 403,
  "code": "APPOINTMENT_NOT_PERMITTED",
  "detail": "The caller is not allowed to schedule this appointment."
}
```

Use least privilege and record the security-relevant action in an audit trail:

```json
{
  "event": "appointment.created",
  "request_id": "req-abc123",
  "actor_id": "user-123456789",
  "client_id": "advising-portal",
  "resource_id": "appointment-987654321",
  "outcome": "success"
}
```

The audit event should help answer:

- Who acted?
- Which client or agent acted?
- What operation was attempted?
- What resource was affected?
- What was the outcome?

> [!Important]
> Documented does not mean safe.
