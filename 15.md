# Document the API contract

Use an OpenAPI specification as a discoverable, machine-readable contract.

Document more than the route:

- operation identifiers and meaningful descriptions;
- request and response schemas;
- required fields, enums, and explicit formats;
- examples of valid requests and responses;
- status codes and Problem Details errors;
- authentication and authorization requirements;
- idempotency and retry behavior;
- rate limits and asynchronous behavior;
- version and deprecation expectations.

The specification should be:

- easy for humans to read;
- usable for generated clients and documentation;
- available where clients and agents can discover it;
- validated in CI so the implementation does not drift.

> [!Important]
> Documentation is part of the contract—not a description written after the fact.
